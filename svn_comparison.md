# SVN vs Git

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?
В Git ветка — это просто указатель на коммит (файл размером ~41 байт).
Создание/переключение — мгновенно, не затрагивает рабочую директорию.
В SVN ветка — это физическая копия директории внутри репозитория
(через `svn copy`). Она дублирует файлы на сервере, операция тяжёлая
и медленная, особенно на больших проектах.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?
Нет. SVN — централизованная система: история и репозиторий находятся
только на сервере. Коммит = отправка изменений на сервер.
Без сети можно лишь редактировать файлы локально, но зафиксировать
изменения (`svn commit`) нельзя. В Git коммит делается локально,
сеть нужна только для push/pull.

## 3. В каких сценариях SVN до сих пор предпочтительнее Git?
- Legacy-проекты (госсектор, банки), где миграция дороже поддержки.
- Огромные бинарные ассеты (графика, CAD), где полная копия
  репозитория у каждого разработчика нецелесообразна.
- Жёсткое централизованное управление доступом к файлам
  (path-based авторизация в SVN проще).
- Команды без практики распределённой работы и с простым линейным
  процессом.
